UnifiedAI · TypeScript SDK

One SDK. Many models.

@unifiedai/sdk is the TypeScript client for the UnifiedAI platform. It brokers chat, images, audio, video, embeddings and files across every provider in the catalog behind three familiar wire shapes — and adds the ecosystem surface (artifacts, projects, memory, storage, a jailed file workspace, an agent loop) that lets independent apps interoperate on a user’s behalf.

  • Anthropic

  • Meta
  • Mistral
  • xAI

  • NVIDIA
  • Amazon
  • … and every other author in the catalog

The logos above are rendered by the SDK’s own getProviderLogo() — inline data URIs, light and dark variants, no bundler config. This page is built out of the thing it documents.

Install
Not on npm. Install from GitHub — and trustedDependencies is load-bearing. See Install.

Context

Where the SDK fits

The SDK talks to two backends, and knowing which is which explains almost every URL you will see. unified-api is the model gateway: every model call, every file, the ecosystem surface, plus the OAuth token and revoke endpoints. base-api owns identity: login, accounts, and the OAuth authorize page.

In practice the SDK points at unified-api for everything and only touches base-api during the browser leg of an OAuth sign-in.

EndpointDefault hostOwned by
/oauth/authorizeweb.unifiedai.appbase-api
/oauth/tokenapi.unifiedai.appunified-api
/oauth/revokeapi.unifiedai.appunified-api
/api/v1/* — models, chat, files, storage, fs, ecosystemapi.unifiedai.appunified-api
Why you care

The only consumer-visible consequence is that the sign-in page lives on a different host than the API. Everything else is one base URL.

Step 1

Install

Not published to npm

bun add @unifiedai/sdk returns a 404 — the package name is unclaimed on the public registry. Install from GitHub or a local path instead.

Install from GitHub
bun add @unifiedai/sdk@github:greedyafinc/uni-sdk#main

# Or pin a commit — the version field moves slower than main.
bun add @unifiedai/sdk@github:greedyafinc/uni-sdk#<sha>

The package ships no build output: dist/ is gitignored and produced by the prepare script at install time. Bun blocks lifecycle scripts by default, so you must trust the dependency or dist/ is never built and every import fails to resolve.

package.json — required
{
  "dependencies": {
    "@unifiedai/sdk": "github:greedyafinc/uni-sdk#main"
  },
  "trustedDependencies": ["@unifiedai/sdk"]
}

Inside this workspace, apps use a file: reference instead ("@unifiedai/sdk": "file:../../uni-sdk") so local SDK edits are picked up without a publish step.

The package is ESM-only. The node entry requires Node 18 or newer and the types target TypeScript 5. GitHub installs require Bun during installation because prepare builds dist/; the repository examples also execute with Bun.

Which entry?

Four entries, one core client
// Browser, Tauri WebViews, Workers, edge, server-side trusted hosts.
// Zero node:* specifiers — bundles without polyfills.
import { UnifiedAI } from "@unifiedai/sdk";

// Node CLIs and desktop apps: adds OAuth (PKCE + loopback + OS keychain).
import { UnifiedAI } from "@unifiedai/sdk/node";

// Optional payloads stay out of the production core bundle.
import { getModelLogo } from "@unifiedai/sdk/logos";
import { FakeSyncServer } from "@unifiedai/sdk/testing";

The node entry is a runtime superset — same class name, same resources, plus bootstrap(). Pulling it into a browser bundle drags in node:* and the native @napi-rs/keyring, which fails the build. The SDK’s own build enforces the reverse direction: a structural check fails if the browser bundle ever picks up either.

The keychain dependency is optional

The node entry re-exports the same resource surface as the browser entry. @napi-rs/keyring is an optional dependency: if it cannot install or the OS keychain is locked, bootstrap continues to desktop handoff and browser PKCE.

Step 2

Quickstart

A working call, start to finish. This is the whole surface in miniature: construct with a token, pick a wire shape, read the result.

First call
import { UnifiedAI } from "@unifiedai/sdk";

const sdk = new UnifiedAI({ token: process.env.UNIFIED_TOKEN });

const res = await sdk.chat.completions.create({
  model: "gpt-4o",
  messages: [
    { role: "system", content: "You are terse." },
    { role: "user", content: "Why is the sky blue?" },
  ],
  max_tokens: 300,
});

console.log(res.choices[0]?.message.content);
console.log(res.usage.total_tokens);

Streaming is the same call with one option — and no await:

Streaming
const stream = sdk.chat.completions.create({
  model: "gpt-4o",
  messages: [{ role: "user", content: "Write a haiku about TCP." }],
  stream: true,
  stream_options: { include_usage: true },
});

for await (const chunk of stream) {
  process.stdout.write(chunk.choices[0]?.delta.content ?? "");
}

// Populated once the stream drains and a usage-bearing chunk arrived.
console.log(stream.usage?.tokens_per_second);
stream: true returns synchronously

The overloads key off the literal type. stream: true returns the UnifiedStream directly — there is no promise to await. Passing a variable typed boolean matches neither overload and is a compile error (TS2769); you do not get a union back. Branch at the call site instead.

Concepts

Auth

There are exactly two modes, and the token option decides which one you get. Everything else — API keys, OAuth tokens, host-supplied bearers — is a variation on these two.

ModeTriggerAvailable onFor
Trusted-token Set token Both entries Hosts that already have a bearer: web/desktop shells, servers, uapi_ keys
OAuth (PKCE) Omit token, set appId; bootstrap explicitly or on the first request /node only CLIs and installed marketplace apps signing in as the user
There is no apiKey option

UnifiedAIOptions has no apiKey and no baseURL. Passing either in an object literal is a compile error (TypeScript’s excess-property check), not a silent misconfiguration. A uapi_ API key is simply a bearer credential — pass it as token.

Trusted-token mode

token takes a string or an async callback. The SDK calls the callback on every request, so a host can rotate credentials without rebuilding the client.

Host-supplied bearer
import { UnifiedAI } from "@unifiedai/sdk";

const sdk = new UnifiedAI({
  apiUrl: "https://api.unifiedai.app",
  // TokenProvider = string | (() => string | Promise<string>)
  token: async () => readBearerFromSession(),
});

On a 401 the SDK calls your provider once more — single-flighted across concurrent requests — and retries. If it still 401s, it throws UnifiedAIAuthError.

OAuth mode node only

This is the marketplace promise: an installed app authenticates without its own login when UnifiedApp is running. bootstrap() walks a fixed chain and stops at the first hit.

Seamless auth for a CLI
import { UnifiedAI } from "@unifiedai/sdk/node";

const sdk = new UnifiedAI({
  appId: "my-cli",
  signInTimeoutMs: 5 * 60_000,
  onAuthEvent: (event) => console.error("[auth]", event.type),
});

// OS keychain → desktop handoff → system-browser PKCE.
// Optional: the first API request also bootstraps lazily.
await sdk.bootstrap();

console.log("signed in as", sdk.identity().user_id);
const models = await sdk.models.list();
#LegHits when
1OS keychain cacheThis app signed in before on this machine
2Desktop handoff (env port, then discovery file)UnifiedApp desktop is running
3System-browser PKCE (S256) via loopbackEverything else — the user consents once

Session

sdk.session is the observable auth surface — subscribe rather than poll.

Session lifecycle
const unsubscribe = sdk.session.onChange((event) => {
  // "signedIn" | "refreshed" | "signedOut" | "expired" | "error"
  if (event.type === "error") console.error("refresh failed:", event.error);
  if (event.type === "expired") console.error("re-authentication required");
});

await sdk.bootstrap();
// expiresAt is epoch MILLIseconds (TokenSet.expires_at is seconds).
console.log(sdk.session.isAuthenticated(), sdk.session.snapshot().expiresAt);
unsubscribe();
bootstrap() resolving does not guarantee a live token

A keychain hit short-circuits without an expiry check, and the proactive-refresh timer is skipped entirely when the cached token is already stale — only the reactive 401→refresh path recovers it. So bootstrap() can resolve and emit signedIn while holding a dead access token. sdk.session.isAuthenticated() correctly reports false in that window — check it if you need certainty before the first call.

signOut() snapshots the token family, clears memory and keychain, emits signedOut, then revokes the snapshot best-effort. A later request does not silently reopen the browser; call bootstrap() explicitly to sign in again.

Concepts

Three text surfaces

The SDK exposes three parallel text-generation surfaces, each mirroring a different provider wire format so you can port existing code with minimal edits. The choice is about the request/response shape you want, not the model you get — any surface can route to any compatible model.

SurfaceShapeReach for it when
sdk.chat.completionsOpenAI chat/completionsPorting OpenAI code; the most familiar path
sdk.messagesAnthropic MessagesPorting Anthropic code; want finalMessage()
sdk.responsesOpenAI ResponsesUnified multimodal input in one call
Anthropic-style messages
const msg = await sdk.messages.create({
  model: "claude-sonnet-4-5",
  max_tokens: 1024, // required on this surface
  system: "Answer only with valid JSON.",
  messages: [{ role: "user", content: "List three primary colors." }],
});

for (const block of msg.content) {
  if (block.type === "text") console.log(block.text);
}
console.log(msg.stop_reason, msg.usage.output_tokens);

finalMessage() is unique to sdk.messages: stream the request but skip writing an event reducer.

Stream, but only want the result
const stream = sdk.messages.create({
  model: "claude-sonnet-4-5",
  max_tokens: 1024,
  messages: [{ role: "user", content: "Summarize the CAP theorem." }],
  stream: true,
});

// Drains the events for you and assembles the response.
const final = await stream.finalMessage();
console.log(final.content, final.stop_reason);
Multimodal via the responses surface
const res = await sdk.responses.create({
  model: "gpt-4o",
  instructions: "Describe images in one sentence.",
  input: [{
    role: "user",
    content: [
      { type: "input_text", text: "What is in this picture?" },
      { type: "input_image", image_url: "https://example.com/cat.png", detail: "auto" },
    ],
  }],
});
Extended reasoning differs per surface

chat.completions takes thinking: { type: "enabled", budget_tokens? } with budget_tokens optional; messages requires budget_tokens; responses has no typed thinking at all (use the untyped reasoning field). Reasoning text arrives as reasoning_content on both the assembled message and the streamed delta — a non-standard field you will not find in vanilla OpenAI types.

Concepts

Streaming

Every create() with stream: true returns a UnifiedStream: an async-iterable over parsed SSE events. Iterate it, or reach for a surface-specific assembler.

Cancel mid-flight
const stream = sdk.messages.create({
  model: "claude-sonnet-4-5",
  max_tokens: 1024,
  messages: [{ role: "user", content: "Stream a haiku." }],
  stream: true,
});

for await (const event of stream) {
  if (event.type === "content_block_delta" && event.delta.type === "text_delta") {
    process.stdout.write(event.delta.text);
  }
  if (userHitEscape) stream.abort(); // closes the fetch, ends the iterator
}

stream.usage populates once a usage-bearing event lands — message_delta on the Anthropic surface, or a final chunk when you pass stream_options: { include_usage: true } on chat. Read it after the loop. If reading an established stream fails, the iterator throws StreamInterruptedError.

Concepts

Errors

Every SDK error extends UnifiedError and carries a stable code, optional cause, and isUnifiedSdkError: true. HTTP failures additionally extend UnifiedAIError and carry response details.

ClassHTTPExtra fields
BadRequestError400—
AuthenticationError401—
UnifiedAIAuthError401refresh failures; extends AuthenticationError
ForbiddenError403credential accepted but not permitted; refreshing will not help
NotFoundError404—
DeprecatedModelError410isDeprecated; keyed off body code model_deprecated
RateLimitError429retryAfter
UsageLimitError429periodCost, limit, resetAt, isUsageLimit
ServerError5xx—
StreamInterruptedError—reading an established SSE response failed; original transport failure in cause
UnifiedAIErrorotherbase — code, status, body, headers, requestId
RateLimitError and UsageLimitError are siblings, not parent/child

Both are 429, but they mean opposite things. RateLimitError is transient throttling — wait and retry. UsageLimitError is plan-quota exhaustion for the billing period — retrying will not help. UsageLimitError does not pass an instanceof RateLimitError check, so a generic retry wrapper must catch both explicitly. Always check the more specific class first.

Branching on failure mode
import {
  UsageLimitError, RateLimitError, DeprecatedModelError,
  ForbiddenError, AuthenticationError, BadRequestError,
  ServerError, StreamInterruptedError, UnifiedAIError,
} from "@unifiedai/sdk";

try {
  await sdk.chat.completions.create({ model: "gpt-4o-mini", messages });
} catch (err) {
  if (err instanceof UsageLimitError) {
    console.error(`Quota exhausted: $${err.periodCost} / $${err.limit}`);
  } else if (err instanceof RateLimitError) {
    console.error(`Throttled — retry in ${err.retryAfter ?? "?"}s`);
  } else if (err instanceof DeprecatedModelError) {
    console.error("Model retired — select a current model");
  } else if (err instanceof ForbiddenError) {
    console.error("Credential is not permitted for this operation");
  } else if (err instanceof AuthenticationError) {
    console.error("Token invalid or revoked");
  } else if (err instanceof BadRequestError) {
    console.error("Request rejected:", err.body);
  } else if (err instanceof ServerError) {
    console.error("Upstream failure:", err.requestId);
  } else if (err instanceof StreamInterruptedError) {
    console.error("Partial response; retry the stream:", err.cause);
  } else if (err instanceof UnifiedAIError) {
    console.error(`Unexpected ${err.status}:`, err.message);
  } else {
    throw err;
  }
}

Reference

Feature reference

Everything else the client exposes, grouped by what it is for. Expand what you need — full signatures live in the generated API reference (bun run docs).

Model-facing

sdk.models · sdk.usagecatalog & account

models.list() reads the gateway catalog: id, type, capability flags and context size. Pass include: ["author"] to populate the friendly model_author.name that getModelLogo() keys on.

Catalog + logos
import { UnifiedAI } from "@unifiedai/sdk";
import { getModelLogo } from "@unifiedai/sdk/logos";

const { data } = await sdk.models.list({ include: ["author"] });

for (const model of data) {
  if (model.type !== "text") continue;
  console.log(model.id, model.model_author.name, model.context_size ?? "unknown");
  const logoSrc = getModelLogo(model, "dark"); // data: URI, always resolves
}

Before sending multimodal input, gate on the model’s capability flags (image_inp, audio_inp, video_inp, pdf_inp) rather than assuming — they are what the gateway enforces.

Usage meter
import { summarizeUsage } from "@unifiedai/sdk";

// scope: "account" = totals across all of the user's apps.
// Omit it for the default: usage scoped to the calling app.
const usage = await sdk.usage.get({ scope: "account" });
const view = summarizeUsage(usage, { warnThreshold: 0.8 });

console.log(`${view.planName}: ${view.daily.usedLabel}/${view.daily.limitLabel ?? "unmetered"}`);
if (view.daily.isMetered && view.daily.isNearLimit) {
  console.log(`Resets in ${view.daily.resetsInLabel ?? "soon"}`);
}
scope: "account" fails open

A third-party OAuth client stays app-scoped regardless — you get a normal 200 with smaller numbers, not an error. Only present an account-scoped read as authoritative when the client holds a first-party trusted token or a uapi_ key. Guard on isMetered: limitLabel and percent are null on uncapped plans.

sdk.filesupload & reference

Two upload surfaces. upload() is the image-only convenience that also returns a short-lived signed image_url for images.edit. create() is general-purpose (audio, video, PDF) and returns a FileObject with metadata only. Both accept a Blob, File, Buffer, Uint8Array, ArrayBuffer, or a base64 data: URL.

Upload, then reference downstream
// Returns a stable file_id plus a signed URL (~1h).
const { file_id, image_url } = await sdk.files.upload(pickedFile);

const res = await sdk.responses.create({
  model: "gpt-4o",
  input: [{
    role: "user",
    content: [
      { type: "input_text", text: "What's in this image?" },
      { type: "input_image", image_url },
    ],
  }],
});

const { data } = await sdk.files.list();
const { bytes, contentType } = await sdk.files.content(file_id);
await sdk.files.del(file_id);
file_id and image_url both work

The id from upload()/create() is usable as file_id on any multimodal content part across all three text surfaces — the gateway resolves it server-side. Pick whichever reads more naturally at the call site. String sources must be base64 data: URLs; a raw base64 blob or an https:// URL throws.

sdk.images · sdk.audio · sdk.videos · sdk.embeddingsother modalities

images.generate(), images.edit() and images.createVariation(); audio and videos for their respective modalities; embeddings.create() mirrors the OpenAI shape and accepts a single string or an array.

Embeddings
const res = await sdk.embeddings.create({

for (const item of res.data) {

}
sdk.helpersmultimodal part builders

A stateless factory that converts a Blob, Buffer, URL, data-URL or file id into the exact content-part shape each surface expects. The free functions work without a client instance.

Same source, different surface
const imagePart = await sdk.helpers.toImagePart(file, { detail: "high" });

const res = await sdk.chat.completions.create({
  model: "auto",
  messages: [{ role: "user", content: [{ type: "text", text: "What's in this?" }, imagePart] }],
});

// Or without a client — Anthropic-style document part from raw bytes.
import { toMessagesDocumentPart } from "@unifiedai/sdk";
const docPart = await toMessagesDocumentPart(await readFile("./contract.pdf"));
Mime detection blind spot

M4A audio sharing the mp42/isom ISO-BMFF brand resolves to video/mp4, as does any unrecognized ftyp brand. For bare bytes, only an explicit { mimeType } or { format } fixes it — a real File works too, via its own .type. Note PartOptions.filename does not influence detection.

Ecosystem v0.2.0

These give standalone apps the interconnection services that embedded apps get from the desktop shell. They are the newest and least settled part of the SDK — see Stability.

sdk.storagetyped record store

An app-namespaced record store. Declare typed collections and the SDK derives the index set and a file/blob split from the schema. Reach for it when an app needs durable per-app records that follow the user across devices — rather than the model-facing sdk.files.

Typed collection
interface Project extends Record<string, unknown> {
  id: string;
  name: string;
  updatedAt: number;
}

const sdk = new UnifiedAI({ appId: "design-app", token: myToken });
const db = sdk.storage.namespace(); // this app's own read-write namespace
const projects = db.collection<Project>("projects", { key: "id", indexes: ["updatedAt"] });

await projects.put({ id: "p1", name: "Coffee", updatedAt: Date.now() });
const recent = await projects.query({ orderBy: "updatedAt", order: "desc", limit: 20 });
Three things that will bite

No offline fallback. The local IndexedDbBackend was removed; storage is Supabase-only. With no token and no injected backend every call rejects with storage_unavailable. put() is a full replace, not a patch — any field you omit is gone. Read-modify-write to change one field. versions()/revert() always compile regardless of schema.versioned, and silently degrade to [] on a non-versioned collection.

sdk.fsjailed file workspace

A jailed POSIX-style directory tree, keyed by relative paths — the sibling of sdk.storage. Reach for it when an app needs durable project files (source trees, drafts, exported assets). Pair it with fsTools() to drive it from an agent loop.

The app's own workspace
const sdk = new UnifiedAI({ token: () => getAccessToken(), appId: "notes-app" });

// No args = this app's own tree, mode "readwrite".
const ws = sdk.fs.namespace();

await ws.write("drafts/hello.md", "# Hello\n");
const text = await ws.read("drafts/hello.md"); // UTF-8 string
const info = await ws.stat("drafts/hello.md"); // FsStat | null
console.log(ws.id, ws.mode, info?.size, info?.updatedAt);
available() is not a health check

CloudFsBackend.available() unconditionally returns true — it probes nothing. So sdk.fs.available() === true means only “a backend object exists,” not “a call will succeed”; auth and network failures surface later as ordinary HTTP errors. Note also that edit() with an empty oldString silently prepends, and that a missing file or a missing oldString throws edit_not_found while a non-unique match throws edit_not_unique — different codes.

sdk.agent · sdk.actionstool loop & cross-app calls

agent.run() is unopinionated tool-loop scaffolding: it streams a completion, accumulates tool calls, dispatches each to your execute, threads results back, and repeats until the model stops or maxSteps (default 40). The SDK injects no system prompt and no tool policy — your app owns both.

Agent loop with the fs tool pack
import { UnifiedAI, fsTools } from "@unifiedai/sdk";

const result = await sdk.agent.run({
  system: "You are a coding assistant. Use the file tools to do the work.",
  prompt: "Create hello.ts that prints a greeting.",
  tools: fsTools(sdk.fs.namespace()),
});

if (!result.ok) throw new Error(result.error ?? "canceled");
console.log(`served by ${result.model}, ${result.usage?.outputTokens} out`);
run() does not throw for request failures

It resolves with { ok: false, error, errorCode }. A try/catch will not see rate limits or auth failures — branch on result.ok instead. Two corollaries: a throw from your onEvent callback does escape run() (it is invoked outside the internal try/catch during tool dispatch), and ok: true does not mean the model finished — hitting maxSteps returns ok: true with truncated output.

sdk.actions is a separate concern: a cross-app registry where an app declares actions and serves invocations over a pull channel (serve(handlers) polls, runs, responds), so a CLI behind NAT needs no reachable endpoint. The invoker side is invoke() + awaitResult(). Register the app itself first with registerApp().

sdk.artifacts · sdk.projects · sdk.references · sdk.memorycross-app interop

An artifact is a canonical, self-contained versioned snapshot of an app’s work that chat, other apps and external agents can consume. A project is a user-owned container gathering artifacts from different apps. References is the trusted cross-app read path, authorized by project membership rather than a generic cross-namespace read. Memory is an append-only agent ledger.

Publish an artifact, then revise it
const { artifact } = await sdk.artifacts.create({
  kind: "docs/document",
  title: "Q3 Launch Plan",
  content: { blocks: doc.toJSON() },
  text: doc.toPlainText(), // required searchable projection
  projectId,
});

// Later — versions are whole snapshots, not diffs.
const next = await sdk.artifacts.addVersion(artifact.id, {
  content: { blocks: doc.toJSON() },
  text: doc.toPlainText(),
});
console.log(next.version.version); // → 2

Every version carries a required text field — the uniform searchable projection that makes an artifact legible to consumers that do not understand your app’s content format.

Deletions arrive as tombstones

memory.sync() is cursor-based, and deletions arrive as type: "tombstone" appends, never as removals. Mirror the ledger locally without handling that and you silently accumulate deleted rows forever.

Deeper

Advanced

Retry & idempotency

Retry is on by default (3 attempts, exponential backoff with full jitter, 60s total ceiling, Retry-After honored but capped). What gets retried depends on idempotency, and the default for POST is not idempotent:

FailureRetried?
429 — transient rate limitAlways (not gated on idempotency)
429 — usage-limit exhaustionNever — terminal within the billing window
408 / 5xxOnly if the call is idempotent
Network errorOnly if the call is idempotent
AbortNever — user intent propagates immediately
chat.completions does not retry 5xx by default

isIdempotent() treats GET/HEAD/PUT/DELETE/OPTIONS as idempotent and POST/PATCH as not. The text surfaces (chat, messages, responses) POST without opting in, so a 502 or a dropped connection surfaces to you immediately — only transient 429s retry. That is deliberate: a 5xx may arrive after the origin already processed your request, so a blind retry could double-charge.

Two POSTs that are really pure reads opt themselves in: embeddings.create and images.generate retry 5xx and network errors without you doing anything. Everything else — including images.edit and images.createVariation — does not.

Tune retry
const sdk = new UnifiedAI({
  token,
  retry: { maxRetries: 5, initialDelayMs: 250 }, // or `retry: false` to disable
  onRetry: ({ attempt, delayMs, status }) => {
    metrics.increment("sdk.retry", { attempt, status });
  },
});

// Per-call: opt a POST into network/5xx retry when it's safe to repeat.
await sdk.chat.completions.create(body, { idempotent: true });

Local-first discovery node

When the desktop app is running it can host the Ecosystem API on loopback. discoverLocalEcosystem() finds it and hands back a base URL and token — but it is a standalone helper: constructing a client never calls it, and you wire the result in yourself.

Prefer local, fall back to cloud
import { UnifiedAI, discoverLocalEcosystem } from "@unifiedai/sdk/node";

// null when the desktop isn't running (or the discovery file is stale).
const local = await discoverLocalEcosystem({ timeoutMs: 500 });

const sdk = local
  ? new UnifiedAI({ appId: "my-cli", apiUrl: local.baseUrl, token: local.token })
  : new UnifiedAI({ appId: "my-cli" }); // cloud + OAuth bootstrap

Testing & CI node

Every seam in the bootstrap chain is an injectable adapter, so a test can force one branch and assert the others never fire.

Inject the whole chain
import { UnifiedAI, type KeychainAdapter, type TokenSet } from "@unifiedai/sdk/node";

const store = new Map<string, TokenSet>();
const keychain: KeychainAdapter = {
  async get(clientId) { return store.get(clientId) ?? null; },
  async set(clientId, tokens) { store.set(clientId, tokens); },
  async clear(clientId) { store.delete(clientId); },
};

const sdk = new UnifiedAI({
  appId: "my-cli",
  keychain,
  env: { read: () => ({ handoffPort: 4321, clientId: undefined }) },
  discovery: { read: async () => null },
  openUrl: () => { throw new Error("browser leg should not run"); },
  fetch: myFakeFetch, // handoff/token/revoke all go through options.fetch
});
A missing OS keychain is recoverable

A locked, missing, or unavailable keychain is treated as a cache miss. Bootstrap continues through desktop handoff and browser PKCE; inject a keychain adapter in CI when you need a fully non-interactive flow.

Troubleshooting

Indexed by symptom — which is how you usually arrive.

SymptomCause
404 from bun add @unifiedai/sdk Not published to npm. Install from GitHub — Install.
Cannot find module '.../dist/index.js' prepare never ran. Add trustedDependencies: ["@unifiedai/sdk"].
Bundler errors on node:* or @napi-rs/keyring The /node entry reached a browser bundle. Import @unifiedai/sdk or pin @unifiedai/sdk/browser.
TS2353 on apiKey / baseURL No such options. Use token and apiUrl.
TS2769: No overload matches this call stream was a boolean variable, not a literal. Branch at the call site.
Every call 401s right after bootstrap() A stale keychain token short-circuited the chain with no expiry check. Check session.isAuthenticated().
bootstrap() fails with auth_timeout The browser redirect did not arrive within signInTimeoutMs (5 minutes by default). Start sign-in again.
bootstrap() rejects in CI The keychain now falls through; CI still needs a handoff/token source or injected adapters to avoid interactive browser PKCE.
app_not_installed instead of a browser prompt An env-injected handoff port returned 404, which is authoritative for that launched process. A discovery-file 404 is treated as stale and falls through to browser PKCE.
storage_unavailable / fs_unavailable Browser entry with no token and no injected backend. There is no local fallback.
A generic retry wrapper never fires on quota errors UsageLimitError is not a RateLimitError. Catch both.
5xx surfaces immediately with no retry Expected on the text surfaces: POST is non-idempotent by default. Pass { idempotent: true } if the call is safe to repeat.
agent.run() never throws on a rate limit By design — it resolves { ok: false, errorCode }.
Account usage looks too small scope: "account" fails open for OAuth clients — you got app-scoped numbers.

Stability

The package sits at v0.2.0 and the surface is not uniformly settled. Roughly:

BucketSurfaceWhat that means
Stable chat messages responses models usage files embeddings images audio videos helpers — plus core client, session and errors Mirror external wire formats, exercised by the test suite. Safe to build on.
Usable, with caveats storage fs agent — and the node OAuth chain Shipping and used in-tree, but read the callouts above: no offline fallback, available() is not a health check, and run() reports failures in its return value.
Experimental artifacts projects references memory actions Newest surface, zero test coverage, and several routes are marked v1-restricted or Phase 2 in PROTOCOL.md. Expect movement.
Docs that lie

Two in-repo documents are stale in ways that will mislead you. STORAGE-SPEC.md carries a superseded banner — its architecture diagram and backend table describe IndexedDbBackend and OpfsBackend, both of which have been removed. Several fs source comments likewise promise a “local-first” OPFS implementation that does not ship. Where a comment and the code disagree, the code is CloudFsBackend and nothing else.
